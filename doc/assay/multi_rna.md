## Introduction

`multi_rna` is CeleScope's primary pipeline for single-cell RNA-Seq analysis. It runs three steps in order:

1. **sample** — inspect FASTQ files, detect chemistry.
2. **starsolo** — run [STARsolo](https://github.com/alexdobin/STAR) for alignment, cell calling, and UMI counting.
3. **analysis** — post-cell-calling analysis: normalization, PCA, Leiden clustering, marker gene detection, t-SNE visualization, and optional cell-type annotation with [Celltypist](https://www.celltypist.org/).

Works for both single-cell RNA-Seq and single-nuclei RNA-Seq.

## Usage

### 1. Create a genome directory

#### Homo sapiens

```bash
mkdir hs_ensembl_110
cd hs_ensembl_110

wget https://ftp.ensembl.org/pub/release-110/fasta/homo_sapiens/dna/Homo_sapiens.GRCh38.dna.primary_assembly.fa.gz
wget https://ftp.ensembl.org/pub/release-110/gtf/homo_sapiens/Homo_sapiens.GRCh38.110.gtf.gz

gunzip Homo_sapiens.GRCh38.dna.primary_assembly.fa.gz
gunzip Homo_sapiens.GRCh38.110.gtf.gz

conda activate celescope

celescope utils mkgtf \
  Homo_sapiens.GRCh38.110.gtf \
  Homo_sapiens.GRCh38.110.filtered.gtf

celescope rna mkref \
  --genome_name Homo_sapiens_ensembl_110_filtered \
  --fasta Homo_sapiens.GRCh38.dna.primary_assembly.fa \
  --gtf Homo_sapiens.GRCh38.110.filtered.gtf \
  --mt_gene_list mt_gene_list.txt
```

#### Mus musculus

```bash
mkdir mmu_ensembl_110
cd mmu_ensembl_110

wget https://ftp.ensembl.org/pub/release-110/fasta/mus_musculus/dna/Mus_musculus.GRCm39.dna.primary_assembly.fa.gz
wget https://ftp.ensembl.org/pub/release-110/gtf/mus_musculus/Mus_musculus.GRCm39.110.gtf.gz

gunzip Mus_musculus.GRCm39.dna.primary_assembly.fa.gz
gunzip Mus_musculus.GRCm39.110.gtf.gz

conda activate celescope

celescope utils mkgtf \
  Mus_musculus.GRCm39.110.gtf \
  Mus_musculus.GRCm39.110.filtered.gtf

celescope rna mkref \
  --genome_name Mus_musculus_ensembl_110_filtered \
  --fasta Mus_musculus.GRCm39.dna.primary_assembly.fa \
  --gtf Mus_musculus.GRCm39.110.filtered.gtf \
  --mt_gene_list mt_gene_list.txt
```

`--mt_gene_list` specifies the path to a plain-text file containing mitochondrial genes for the reference genome, with one gene symbol per line. During the `celescope utils mkgtf` step, a default `mt_gene_list.txt` file is automatically generated by identifying all genes whose chromosome name, converted to uppercase, is "MT".

For more details about the `mkgtf` command, please refer to [mkgtf.md](../mkgtf.md).

For mixed-genome analysis, typically a human–mouse mixture, please refer to [human_mouse](https://github.com/singleron-RD/human_mouse).

### 2. Generate scripts for each sample

In your working directory, create a shell script named `run.sh`:

```bash
multi_rna \
  --mapfile ./rna.mapfile \
  --genomeDir {path to hs_ensembl_110 or mmu_ensembl_110} \
  --thread 16 \
  --soloCellFilter EmptyDrops_CR \
  --mod shell
```

#### Arguments

`--mapfile`
Required. The mapfile is a tab-delimited text file containing at least three columns. Each line represents one pair of FASTQ files.

* 1st column: FASTQ file prefix
* 2nd column: FASTQ file directory
* 3rd column: Sample name, which will be used as the prefix for all output files
* 4th column: Optional. Celltypist model file name, used for automatic cell-type annotation, e.g. `Immune_All_Low.pkl`. If a sample spans multiple lines, all its lines must carry the same value. Models should match the context of the query data, e.g. `Immune_All_Low.pkl` / `Immune_All_High.pkl` for immune cells from different tissues, where `Low` means low-hierarchy (high-resolution) subtypes and `High` means high-hierarchy (low-resolution) cell types. The full list is in the [Celltypist model catalog](https://www.celltypist.org/models).

Cell-type annotation is optional, and can be skipped in either of two ways:

* **Column omitted** — the mapfile has only three columns. No sample is annotated.
* **Per-sample `None`** — the 4th column is `None` for that sample, while other samples in the same mapfile still name a model.

```bash
$ cat ./no_annotation.mapfile
fastq_prefix1	fastq_dir1	sample1
fastq_prefix2	fastq_dir1	sample1

$ cat ./mixed.mapfile
fastq_prefix1	fastq_dir1	sample1	Immune_All_Low.pkl
fastq_prefix2	fastq_dir2	sample1	Immune_All_Low.pkl
fastq_prefix3	fastq_dir1	sample2	None
```


Example:

Sample 1 has two paired-end FASTQ files located in two different directories, `fastq_dir1` and `fastq_dir2`. Sample 2 has one paired-end FASTQ file located in `fastq_dir1`.

```bash
$ cat ./my.mapfile
fastq_prefix1	fastq_dir1	sample1	Immune_All_Low.pkl
fastq_prefix2	fastq_dir2	sample1	Immune_All_Low.pkl
fastq_prefix3	fastq_dir1	sample2	None

$ ls fastq_dir1
fastq_prefix1_1.fq.gz	fastq_prefix1_2.fq.gz
fastq_prefix3_1.fq.gz	fastq_prefix3_2.fq.gz

$ ls fastq_dir2
fastq_prefix2_1.fq.gz	fastq_prefix2_2.fq.gz
```


`--genomeDir`
Required. The path to the genome directory generated by `celescope rna mkref`.

`--celltypist_model`
Not available as a `multi_rna` argument. Celltypist models are specified per sample in the 4th column of the mapfile; samples left empty or set to `None` skip cell-type annotation. The `.pkl` suffix is optional here — a bare model name such as `Immune_All_Low` is automatically completed to `Immune_All_Low.pkl`.

`--thread`
The recommended number of threads is 16. Using more than 20 threads is generally not recommended, because [the mapping speed of STAR tends to saturate above approximately 20 threads](https://github.com/singleron-RD/CeleScope/issues/197). Default: `16`.

`--mod`
Specifies the script type to generate. Available options include `sjm`, which uses [Simple Job Manager](https://github.com/StanfordBioinformatics/SJM), and `shell`, which generates standard shell scripts. Default: `sjm`.

`--chemistry`
Default: `auto`. Single-cell chemistry. `auto` works for most chemistries. You must explicitly use `GEXSCOPE-MicroBead` for legacy chemistry (no barcode whitelists); use `customized` together with `--pattern` and optional `--whitelist` for fully user-defined combinations.

`--soloCellFilter`
Cell-calling strategy passed to STARsolo. Default: `EmptyDrops_CR`. For details and available values, see the [STARsolo EmptyDrops-like filtering documentation](https://github.com/alexdobin/STAR/blob/master/docs/STARsolo.md#emptydrop-like-filtering).

---

After running:

```bash
sh run.sh
```

a `shell` directory containing `{sample}.sh` files will be generated.

Start the analysis by running:

```bash
bash ./shell/{sample}.sh
```

Please note that `./shell/{sample}.sh` must be executed from the working directory. It should not be run from inside the `shell` directory.

## Main output

* `outs/{sample}_Aligned.sortedByCoord.out.bam`
  Coordinate-sorted BAM file containing reads aligned to the genome.

* `outs/raw/`
  Gene expression matrix containing all barcodes from the barcode whitelist, including both background and cell-associated barcodes.

* `outs/filtered/`
  Gene expression matrix containing only cell-associated barcodes.

* `outs/{sample}_report.html`
  Integrated HTML report for the whole pipeline.

* `outs/{sample}/analysis/rna.h5ad`
  AnnData object written by the `analysis` step, containing the expression matrix, QC metrics, clustering results and embeddings. See [The `rna.h5ad` file](#the-rnah5ad-file) below for its detailed structure.

## The `rna.h5ad` file

The `analysis` step writes an AnnData object to `outs/{sample}/analysis/rna.h5ad`, which can be loaded directly with Scanpy:

```python
import scanpy as sc

adata = sc.read_h5ad("./outs/{sample}/analysis/rna.h5ad")
```

Contents:

- `adata.X`: log1p-normalized expression after scaling (`sc.pp.scale`, `max_value=10`, i.e. the z-scored expression used for PCA). Note that this matrix is **not** the raw counts.
- `adata.layers["counts"]`: raw UMI counts.
- `adata.layers["normalized"]`: size-factor-normalized (10,000 counts/cell) log1p-transformed expression, which is used for marker gene detection (`sc.tl.rank_genes_groups`).
- `adata.var["mito"]`: boolean flag marking mitochondrial genes (from the reference's `mt_gene_list`, otherwise cell names starting with `MT-`).
- `adata.obs["total_counts"]`, `adata.obs["n_genes_by_counts"]`: total UMI and detected gene number per cell.
- `adata.obs["pct_counts_mito"]`: mitochondrial UMI fraction per cell.
- `adata.obs["cluster"]`: Leiden cluster assignments (resolution `1.2`, key `cluster`).
- `adata.obsm["X_pca"]`: 50-component PCA embedding.
- `adata.obsm["X_tsne1"]`, `adata.obsm["X_tsne2"]`: t-SNE coordinates (Seurat-style names, as used in `tsne_coord.tsv`).
- `adata.obsm["X_umap"]`: UMAP embedding.
- `adata.uns["rank_genes_groups"]`: Wilcoxon marker gene testing results (same content as `outs/{sample}/analysis/markers.tsv`).
- `adata.obs["predicted_cell_type"]`, `adata.obs["cell_type_confidence"]`: present only when Celltypist annotation was run, giving the predicted cell type per cell and the corresponding maximum prediction probability.

Since `adata.X` is the scaled matrix, use `adata.layers["counts"]` when starting a new analysis from raw counts:

```python
adata.X = adata.layers["counts"].copy()
sc.pp.normalize_total(adata, target_sum=1e4)
sc.pp.log1p(adata)
```

## Seurat `CreateSeuratObject`

When using Seurat's [`CreateSeuratObject`](https://www.rdocumentation.org/packages/Seurat/versions/3.0.1/topics/CreateSeuratObject), the default value of `names.delim` is an underscore (`_`). Since cell barcodes are also separated by underscores, for example `ATCGATCGA_ATCGATCGA_ATCGATCGA`, using the default `names.delim = "_"` may incorrectly set `orig.ident` to one segment of the barcode.

This issue can be avoided by setting `names.delim` to another character, such as `"-"`:

```r
seurat.object = CreateSeuratObject(
  matrix,
  names.delim = "-",
  project = "sample_name"
)
```

## Additional matrix filtering

After completing the `multi_rna` workflow, you can run `celescope rna cells` on the existing results to re-perform cell calling (forced cell number, `min_gene`, `max_mito`, or `soloCellFilter`).

For a full reference of arguments and usage examples, see [cells.md](cells.md).
